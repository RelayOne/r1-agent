## Top 10 by Impact

These are the highest-impact items where the V2 governance promise is compromised — fix these first.

1. **web-chat-ui — main.tsx is a placeholder; the chat UI never mounts.** `web/src/main.tsx:14-26` renders a static "scaffolding ready" card. The 25 implemented components, 24 stories, daemon store, routes, hooks, all exist as code but are dead at runtime. Item 41 (router wiring) is provided as a `buildRouter` factory that no one calls. Severity: HIGH. Effort: M (wire router + ThemeProvider + ThreeColumnShell into main.tsx).

2. **anti-truncation / cortex-concerns — AntiTruncLobe publishes Notes to a LOCAL shadow Workspace, not `cortex.Workspace`.** `internal/cortex/lobes/antitrunc/lobe_wrapper.go:29-269` declares `Workspace`, `Note`, `Lobe`, `LobeKind`, `NoteSeverity` as local types. Cortex-core IS merged, but the type aliases were never swapped in. Result: AntiTruncLobe's critical Notes are invisible to `Cortex.PreEndTurnGate` (which reads from `cortex.Workspace.UnresolvedCritical()`), invisible to the durable bus, invisible to TUI/web surfaces. The end-to-end "gate refuses end_turn" promise relies on Notes flowing through the real Workspace, so this nullifies the entire layered defense for cortex-augmented missions. Severity: HIGH. Effort: M (replace local types with cortex aliases + smoke-test the integration).

3. **cortex-core item 13 — pre-warm cache key does NOT match main thread.** `internal/cortex/cortex.go:325-327, 343-345` calls `runPreWarmOnce` with `SystemPrompt=""` and `Tools=nil`. The whole point of pre-warm is cache parity (spec gotcha #5). With empty inputs the cache entry is on a different key than the agentloop's main turn, so the pre-warm fires every interval but never reduces main-turn latency. Severity: HIGH. Effort: M (extend Config with SystemPrompt+Tools or re-route through agentloop's prompt builder).

4. **web-chat-ui item 9 — pinned dependency drift across React/Vite/Vitest/ai-sdk-elements.** `web/package.json` ships React 19.2 (spec: 18.3), Vite 7 (spec: 6), Vitest 4 (spec: 2.1); `@ai-sdk/elements` is absent (replaced by `ai`+`@ai-sdk/react`). Several test/E2E patterns in the spec assume the older API surface (e.g. `useChat` from `@ai-sdk/react ^6` not `^3`). The drift creates a hidden compatibility risk — the spec's listed component cards (`<ToolCard>`, `<ReasoningCard>`, `<PlanCard>`) reference `@ai-sdk/elements` primitives that don't exist in the installed packages. Severity: HIGH. Effort: M (audit each component's imports, document deviation OR re-pin).

Effort: S (add workflow file).
