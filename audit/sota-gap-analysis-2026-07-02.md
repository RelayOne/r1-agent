# SOTA gap analysis — r1 agent harness vs state of the art (2026-07-02)

Method: 8 web-research agents (verification, context, planning, multi-agent, learning, tool-safety, benchmarks, harness-arch), each adversarially fact-checked against primary sources; then code-reading agents mapped each axis onto r1; a chief-architect agent synthesized a prioritized gap list.

## Thesis

Make the native, harness-owned agentloop the measured and self-improving path — and prove it. The one indispensable move is to wire r1's own agent into its own sealed hidden-test benchmark (currently a no-op: notWiredR1Invoker + a bench that bypasses the container/hidden-test/honesty judge), because without a working self-eval every "toward SOTA" change below is unfalsifiable. With measurement live, the next-highest leverage-per-effort wins are closing the cross-session learning loop (memory/wisdom never reach the native path and recall is exact-hash-only) and removing the two structural taxes on the native PLAN->EXECUTE->VERIFY path: an always-on 30-turn plan phase and lossy tool_result truncation that throws away the agent's own observations.

## Per-axis SOTA summaries

### Verifying AI-generated code changes in autonomous coding agents (SWE-bench era, 2024-2026)
The dominant and only reliably-proven verification signal in 2024-2026 is execution: the top SWE-bench agents write a reproduction script, run it to confirm the bug, patch, and re-run — plus run existing/regression tests to guard against breakage. The strongest leaderboard systems layer test-time compute on top: generate N candidate patches, then select with LLM-generated tests via functional (execution-based) majority voting and/or a learned critic model. Concretely: Agentless (localize→repair→validate) lifts SWE-bench Lite from 25.7% (voting only) to 32.0% purely via reproduction+regression validation; OpenHands goes 60.6%→66.4% with 5 samples + a trained critic; CodeMonkeys hits 57.4% via test-script voting + a selection trajectory. Notably, the frontier model vendors (Anthropic's Claude scaffold, Devin) rely mostly on in-loop self-correction from execution feedback rather than ensembles or separate verifiers — Anthropic's published scaffold is deliberately minimal (bash + edit tools, repro-script workflow, no verifier/ensemble described). The load-bearing caveat: test-based verification is itself leaky — independent studies (the "Are Solved Issues Really Solved" study, UTBoost) show ~8-11% of test-passing "plausible" patches are actually incorrect, inflating reported scores by ~6 points, so passing tests ≠ correct, and LLM-as-judge is a weak substitute (style bias, 60-68% expert agreement).

### State-of-the-art context engineering for coding agents (2024-2026): repository-level retrieval, code-graph/AST ranking, agentic vs embedding retrieval, compaction, prompt caching, long-context vs RAG
The 2026 SOTA has converged on agentic, just-in-time context assembly rather than one-shot embedding RAG. The best harnesses (Claude Code, OpenHands, SWE-agent, Cursor's agent) drive an iterative grep/glob/read loop that follows import chains and call graphs, treating the context window as a finite "attention budget" to be curated, not filled. Independent evaluation supports a "bitter lesson": on ContextBench, the trivial bash-only mini-SWE-Agent matches or beats elaborate scaffolding, and embedding-first Agentless posts the lowest file-level F1 (0.390 vs 0.634), so the differentiator is increasingly the frontier model plus disciplined context hygiene, not clever retrieval. Two economic/engineering multipliers separate the best from the rest: (1) cache-stable, append-only context that preserves the KV prefix (Anthropic reports up to 90% cost / 85% latency savings; an independent arXiv study measures 41-80% cost and 13-31% TTFT gains), and (2) compaction/condensation plus sub-agent context isolation that turn quadratic long-horizon cost into roughly linear (OpenHands' LLM condenser: ~2x cheaper per turn at equal SWE-bench score). Structural AST/graph ranking (Aider's tree-sitter + PageRank repo map) and trained semantic search (Cursor) are useful complements to grep, but long-context "dump the whole repo" remains a weak sole strategy because multi-needle recall collapses to ~60% and lost-in-the-middle costs 5-15 points.

### Planning & decomposition for autonomous coding agents (2024-2026)
The dominant SOTA architecture is NOT elaborate upfront planning or tree search — it is a thin interleaved reason-act loop (ReAct/CodeAct lineage) run by a frontier model over a well-engineered Agent-Computer Interface (ACI). SWE-agent (NeurIPS 2024) showed the interface itself roughly doubles GPT-4's SWE-bench score, and OpenHands' CodeAct agent (ICLR 2025) unifies all actions into a single executable-code space and interleaves think-act-observe rather than planning-then-executing. Explicit plan-then-execute helps mainly for scoping/decomposing well-specified long-horizon tasks (Devin's own 2025 review: it handles clear upfront scope but degrades badly on mid-task requirement changes) and actively hurts on ambiguous/dynamic tasks via 'overthinking' (analysis paralysis, rogue actions, premature disengagement — Cuadron et al. 2025 show higher overthinking correlates with lower resolve rate). MCTS/tree-search (SWE-Search, DARS, RethinkMCTS) delivers real paper gains (~23% relative on SWE-bench) but is largely absent from production due to cost; best-of-N rollouts with a verifier is the pragmatic test-time-scaling substitute actually deployed. Marginal SOTA now concentrates in verification — execution feedback, self-generated tests, process/outcome reward models, and external verifiers — consistent with Kambhampati's LLM-Modulo thesis that LLMs should generate candidates but not self-certify. Note: SWE-bench Verified was deprecated by OpenAI in Feb 2026 over contamination, so headline resolve rates (frontier models mid-60s to ~70% on the harder SWE-bench Pro; aggregator claims of 90%+ on Verified should be treated skeptically) must be read with test-design caveats.

### Continual learning & memory for coding agents (2024–2026)
The field splits into two tracks that barely touch. (1) Agentic memory infrastructure — mem0, Letta (ex-MemGPT), Zep — is real and widely deployed (mem0 ~41k GitHub stars, an integration option in AWS Bedrock AgentCore), but is benchmarked almost entirely on conversational recall (LOCOMO, LongMemEval), and those SOTA claims are actively contested: on LOCOMO a plain full-context baseline (~73 J) beats mem0 (~68), grading prompts differ across vendors ("be generous"), and mem0/Zep publicly dispute each other's numbers. (2) Continual/experiential learning for task-doing agents — Reflexion (self-reflection memory), ExpeL (cross-task success/failure insights), Voyager-style executable skill libraries, and experience-replay/workflow induction (Agent Workflow Memory, Contextual Experience Replay) — shows large real gains, but overwhelmingly in games (Minecraft), web navigation (WebArena/Mind2Web) and QA, not production software engineering. For coding specifically, cross-run memory that improves task success (accuracy) is essentially unproven: the only controlled coding-memory study (vendor-run) found memory did not raise code quality at all and only cut cost/turns ~22–40% on complex tasks; SWE-Bench-CL proposes the continual-learning eval but reports no actual results; and SWE Context Bench finds autonomous retrieval of prior context is often net-harmful (only oracle summaries reliably help). In practice, the continual learning that actually ships in coding tools is human/agent-curated markdown context (CLAUDE.md, AGENTS.md, Cursor rules, Cline Memory Bank) and file-based skills (Anthropic Agent Skills), which are ubiquitous but have no rigorous cross-run success benchmark.

### Tool-use, sandboxing, and safety for autonomous coding agents (process isolation, worktree/branch isolation, permission models, prompt-injection defense, secret handling, atomic multi-file edits, patch-apply reliability, destructive-action prevention) — 2024-2026
The 2026 SOTA is defense-in-depth built from four layers, not one silver bullet: (1) OS-level sandboxing of the shell/Bash tool — Anthropic's open-sourced sandbox-runtime uses sandbox-exec/Seatbelt on macOS and bubblewrap on Linux with a Unix-domain-socket egress proxy, and OpenAI Codex uses Seatbelt (macOS) and bubblewrap+Landlock+seccomp (Linux), both refusing to run a command if the requested sandbox can't be enforced; (2) deny→ask→allow permission rules plus PreToolUse hooks and hard circuit-breakers on rm -rf / and ~; (3) git-worktree/branch-per-agent isolation for parallel agents (Claude Code Agent(isolation:worktree), Cursor 2.0's up-to-8 agents); and (4) reversibility via checkpoint/rewind. For file edits, the field has converged on model-emitted search/replace blocks backed by a multi-tier fuzzy-match cascade (Cline's 4-tier, OpenCode's 9-layer, Anthropic's str_replace, Codex's context-anchored apply_patch) — line-numbered unified diffs largely lost outside GPT-4-Turbo-era models, and git provides the atomic multi-file transaction (stage-all → build-gate → merge). The honest gap is safety: independent research (arXiv 2601.17548) finds ~100% of tested coding agents (Claude Code, Cursor, Copilot) are vulnerable to prompt injection, principled defenses like Google DeepMind's CaMeL remain research-only (77% AgentDojo utility vs 84% undefended, not shipped in any mainstream coding agent), and even the best deployed sandbox shipped multiple real bypasses in 2025-2026 (Claude Code's SOCKS5 null-byte egress bypass across ~130 releases; CVE-2025-66479 fail-open). ### Open-source AI coding-agent HARNESS architecture (2024–2026): the load-bearing scaffolding around the model

Tools are the many-typed-JSON model PLUS a real bash action (internal/tools/tools.go:154, 938) with path-confinement (resolvePath:1100), read-before-edit guard, and cascading str_replace. The bus (internal/bus/bus.go) is a durable WAL-backed append-only event stream with causality, hooks, delayed events, and Replay (bus.go:757) — but it is an observability/coordination channel, NOT the loop's memory (tool output in EventToolPostUse is truncated to 1024 bytes, loop.go:896). MCP is a first-class subsystem: internal/mcp/registry.go trust-gates + circuit-breaks servers over stdio/sse/http and merges MCP tools into the same pool as native tools (native_runner.go:183-231), with mcp_tool_search/mcp_resource_list/read for discovery (tools.go:403-440). Safety: risk taxonomy in internal/consent/workflow.go (RiskLow/Medium/High/Blocked:29-32) wired as a binary hub ConsentGate (cmd/r1/main.go:4607); Phase.ReadOnly excludes write tools (native_runner.go:133); scan/hooks/rbac guards; pre-merge snapshot.Take/Restore (workflow.go:1189/1251) and per-phase checkpoint.Store of git metadata (workflow.go:391/550). Container isolation (internal/engine/container.go wrapInDocker: --network=none, --cap-drop=ALL, no-new-privileges) exists but only for the CLI pool runner. Compaction in the native hot path is a single strategy: buildNativeCompactor keeps first msg + last 6 and truncates middle tool_results (native_compact.go:32), gated on a chars/4 estimate (loop.go:502). Parallelism is process-level task dispatch across git worktrees via internal/scheduler.
